人类群星闪耀时

交互式科学家群星 Web 体验

一、Demo 简介

是什么：「人类群星闪耀时」是一个纯前端单文件交互式 Web 体验作品，以深色星空为载体，将 20 位中外科学家化作漫天星辰。用户在星空中漫游、点击星点即可触发该科学家的三段式沉浸式启动流程（诗意名言 → 关键时间线动画 → 全屏详情面板），还包含独立的「星之所向」抽卡页面，随机抽取一位科学家并附带电影级镜头放大过渡。

面向谁：对科学史与人类文明怀有敬意的学习者、科普爱好者、以及喜欢沉浸式交互体验的年轻用户。作品既是科普学习材料，也是一种诗意的文化致敬。

主要功能

星图漫游 · 群星点击探索

首页是一片深色银河星空，20 位科学家（南仁东、哥白尼、牛顿、爱因斯坦、霍金、屠呦呦……）以发光圆点的形式散布其中，星点带有长周期显隐与粒子飘动效果。鼠标悬停时星辰高亮放大，点击进入该科学家的详情流程。

▲ 首页星空全景：标题 + 银河 + 20 颗星辰

三段式沉浸启动流程

每位科学家点击后依次呈现：① 诗意名言过渡页（如"南仁东：感官安宁，万籁无声"）② 关键时间线动画过渡页（可跳过）③ 全屏详情面板，含人物简介、名言金句、代表贡献、关键时间线、人物配图（顶部 banner + 圆形头像 + 简介照片栏三处配图）。

▲ 伽利略详情页：顶部 banner + 圆形头像 + 简介文字

星之所向 · 抽卡页面

独立页面 draw.html，底部"触碰星辰"按钮随机抽取一位科学家。点击后触发电影级序列：圆形光芒旋转爆发 → 星星斜向坠落带尾光 → 镜头跟随主体放大（背景星点辐射后退模拟长焦变焦）→ 全白闪光 → 全黑 → 跳转至该科学家详情页，人物出现。

▲ 星之所向：金色标题 + 5 层群山 + 椭圆玻璃按钮

二、Demo 创作思路

灵感来源：作品名借用茨威格《人类群星闪耀时》——那些"人类群星闪耀"的瞬间，正是科学家们用一生照亮文明前进方向的时刻。把科学家比作星辰，既是对"仰望星空"这一科学家群像的诗意隐喻，也呼应了南仁东建造"中国天眼"仰望宇宙的故事。

想解决的问题：传统科普页面往往以列表/卡片平铺，信息密度高但情感浓度低，用户难以产生"与历史人物对话"的沉浸感。本作品尝试把"了解一位科学家"包装成一次仪式感十足的旅程——从星空中发现一颗星，到名言叩门，到时间线铺陈，最后才进入完整详情，让学习过程本身具有节奏感与诗意。

为什么做这个方向：选择 Web 单文件形态，是因为它即开即用、零部署成本，最适合作为大赛 Demo 传播；选择"星空 + 科学家"主题，是因为视觉上能用 Canvas 发挥出沉浸感，内容上又能承载真实有价值的科普信息，做到"好看"与"有用"兼得。在交互设计上刻意区分了"自由探索（首页星图）"与"随机抽取（星之所向）"两种模式，前者主动学习、后者带有盲盒惊喜感，覆盖不同学习心态。

步骤 4：流星 cinematic 镜头放大序列（2026/7/5）

这是开发中最复杂的部分。需求是"流星滑落时镜头不断放大流星，背景渐变为纯黑，模拟长焦变焦，最后流星占满画面 → 全白 → 全黑 → 出现人物"。TRAE 经过 4 轮迭代调试：

  • 第 1 版：CSS transition 一次性 scale，镜头没跟上主体
  • 第 2 版：流星 fixed 在屏幕中心，但缺乏坠落动态感
  • 第 3 版：流星沿斜向轨迹坠落，镜头 transform-origin 实时跟随
  • 第 4 版（最终）：流星世界坐标移动 + 镜头 translate 公式 cx - meteorX*zoom 让主体始终在视觉中心 + 背景 canvas 星点辐射位移（每颗星点按 depth 沿相对中心方向飞散）+ 全白/全黑遮罩层

步骤 5：人物图片智能处理与接入（2026/7/5）

用户提供 16 张中文命名的科学家图片（含水印、尺寸不一、头部位置歪斜）。TRAE 用 Python + Pillow + numpy 自动化处理：

  • 检测每张图人物头部位置（基于亮度方差）
  • 以头部为视觉中心智能裁剪为 600×800 竖版 3:4 肖像
  • 去掉底部 8% 规避水印
  • 批量替换 17 位科学家详情页的 avatar-core、顶部 banner、简介照片栏（detail-figure）三处图片
  • 3 位无图科学家（哥白尼、达尔文、钱三强）改为纯黑 banner + 单字 fallback

步骤 6：细节打磨与 Bug 修复

开发过程中 TRAE 协助修复多个关键 bug：

  • 首页随机流星 cinematic 误触发导致"一进去就跳转好几个人物"——通过 consumed 标记防止重复消费
  • 抽卡跳转后误显示加载页——URL 参数识别后立即隐藏 loader
  • 星辰点击互动范围太小——扩大检测半径至 Math.max(48, radius×10)
  • 图片栏插入位置错误导致 DOM 结构塌陷——正则修复 16 个面板的标签嵌套

五、开发心得

TRAE 让"想法→成品"的链路前所未有的短。本作品从星空视觉、科学家数据、抽卡交互到镜头放大序列，全部通过自然语言对话完成，TRAE 能准确理解"长焦变焦""背景辐射后退""三段式启动流程"这类带有视觉/交互专业术语的需求，并直接产出可运行代码。

最有价值的瞬间是调试流星镜头放大时，TRAE 能基于我的反馈（"镜头没跟上主体""主体要往下坠落""背景要相对向后位移"）逐版迭代，最终用 translate(cx - meteorX*zoom, cy - meteorY*zoom) scale(zoom) 这个公式让流星世界坐标移动的同时始终映射到屏幕中心，背景星点按 depth 辐射位移——这种"用对话精修视觉细节"的体验是传统开发方式难以企及的。

单文件交付也是 TRAE 的优势之一，整个作品主文件就一个 index.html（约 3700 行），无需构建工具、无依赖安装，解压即用，非常适合作为大赛 Demo 传播。
